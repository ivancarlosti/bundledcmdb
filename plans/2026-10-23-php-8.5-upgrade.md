# Plan: PHP 8.5 Runtime Upgrade

## Overview

Move the Bundled CMDB runtime from PHP 8.4 to PHP 8.5, align the Composer
platform constraint with the new runtime, and remove the only construct in the
codebase that is deprecated in PHP 8.5.

| Item | Before | After |
|------|--------|-------|
| Docker base image | `php:8.4-fpm-alpine` | `php:8.5-fpm-alpine` |
| Composer platform requirement | `"php": "^8.2"` | `"php": "^8.5"` |
| Deprecated calls | 4x `curl_close()` in `auth_keycloak.php` | removed |

The Docker image is the only place the runtime version is defined
(`docker/docker-compose.yml` consumes the published image), so CI needs no
changes: `.github/workflows/build.yml` builds whatever `Dockerfile` declares.

## Availability & dependency check

- `docker manifest inspect php:8.5-fpm-alpine` returns a valid multi-arch OCI
  index (`linux/amd64` and `linux/arm64`), so the release pipeline can keep
  building both platforms without changes.
- `aws/aws-sdk-php` 3.402.0 (latest at the time of writing) requires
  `php >=8.2`, therefore it supports 8.5.
- `ext-pdo`, `ext-curl` and `ext-json` remain available; `docker-php-ext-install
  mysqli pdo pdo_mysql` is unchanged on the 8.5 Alpine image.
- The `vendor` build stage still uses the official `composer:2` image with
  `--ignore-platform-reqs`; the flag is required because the build stage does
  not have the MySQL extensions installed. Composer platform resolution is
  therefore unaffected by the `php` constraint bump.

## PHP 8.5 compatibility audit

Every backward-incompatible change / deprecation from the PHP 8.5 `UPGRADING`
notes was checked against this codebase:

| PHP 8.5 change | Used here? | Notes |
|----------------|-----------|-------|
| `curl_close()` deprecated (handles are freed automatically) | **Yes** | 4 calls in `auth_keycloak.php` — removed |
| Non-canonical casts `(integer)`, `(boolean)`, `(double)`, `(binary)` | No | `grep` found none |
| `${var}` string interpolation (deprecated in 8.2) | No | `grep` found none |
| `__sleep()` / `__wakeup()` soft-deprecated | No | no magic serialisation methods |
| `mysqli_execute()` alias deprecated | No | app uses PDO only |
| `null` as array offset / in `array_key_exists()` | No | all keys are strings |
| `finfo_close()`, `imagedestroy()`, `xml_parser_free()` deprecated | No | extensions not used |
| `Reflection::setAccessible()`, `SplObjectStorage::attach()` deprecated | No | not used |
| PDO `FETCH_GROUP`/`FETCH_PROPS_LATE` constant changes | No | only `FETCH_ASSOC` / `FETCH_COLUMN` |
| Session data with `|` in keys now warns | No | session keys are `user_email`, `company`, `role`, `lang` |
| Uncomparable-object loose comparison to bool | No | no object comparisons |
| Destructuring non-arrays / out-of-range float→int casts warn | No | no such casts |

Result: the application code is already PHP 8.5 compatible apart from
`curl_close()`.

## File-by-file changes

### 1. `Dockerfile`

```diff
-FROM php:8.4-fpm-alpine
+FROM php:8.5-fpm-alpine
```

### 2. `composer.json`

```diff
-        "php": "^8.2",
+        "php": "^8.5",
```

### 3. `auth_keycloak.php`

`curl_close()` is a no-op since PHP 8.0 and deprecated in 8.5. Both call sites
(`getToken()`, `getUserInfo()`) drop the call; the `CurlHandle` is released
automatically when `$ch` goes out of scope.

```diff
         $response = curl_exec($ch);
         if ($response === false) {
             error_log('Keycloak Token Error: ' . curl_error($ch));
-            curl_close($ch);
             return null;
         }
-        curl_close($ch);
```

## Verification

```bash
# 1. Build the image (also proves the 8.5 base image pulls)
docker build -t bundledcmdb:php85 .

# 2. Runtime version + enabled extensions
docker run --rm bundledcmdb:php85 php -v
docker run --rm bundledcmdb:php85 php -m | grep -E 'pdo|mysqli|curl|json'

# 3. Lint every PHP file on 8.5
docker run --rm -v "$PWD":/src:ro --entrypoint sh bundledcmdb:php85 -c \
  'find /src -name "*.php" -not -path "*/vendor/*" -print0 | xargs -0 -n1 php -l'

# 4. Composer manifest still valid
docker run --rm -v "$PWD":/src:ro --entrypoint sh composer:2 -c \
  'cd /src && composer validate --no-check-publish'

# 5. Deprecation smoke test against a seeded MariaDB container:
#    log in through a temporary dev shim, browse main.php / asset.php /
#    manage_permissions.php with error_reporting=E_ALL and grep the FPM
#    log for "Deprecated:".
```

The image built for this change was smoke-tested against a throwaway
`mariadb:11.4` container with seeded demo data; the same container was used to
capture the screenshots documented in
[`2026-10-23-readme-screenshots.md`](2026-10-23-readme-screenshots.md).

### Verified results (2026-10-23)

- `php -v` inside the image: **PHP 8.5.12 (cli) (NTS)**, OPcache 8.5.12.
- Extensions present: `PDO`, `pdo_mysql`, `mysqli`, `curl`, `json`.
- `php -l` on all 12 application PHP files: no syntax errors.
- `composer validate --no-check-publish`: manifest valid; the only warning is
  the pre-existing missing `license` field.
- Runtime smoke test against MariaDB 11.4.13 with `error_reporting=E_ALL`,
  `log_errors=On`: `index.php`, `main.php` (pt_BR and es_MX),
  `asset.php?id=1`, `manage_permissions.php`, `export.php` and `logout.php`
  returned 200/302 and produced **zero** `Deprecated:`, `Warning:` or
  `Fatal error` lines in the FPM log. A deliberate `E_USER_DEPRECATED` request
  was sent first to confirm that the log capture worked.
- Final image size: 333 MB.

## Risks

| Risk | Mitigation |
|------|-----------|
| Base image not yet available for arm64 | Verified via `docker manifest inspect` before merging |
| Third-party library incompatibility | `aws/aws-sdk-php` requires `>=8.2`; everything else is app code |
| Extension build failure on Alpine | `mysqli`, `pdo`, `pdo_mysql` build the same way on 8.4 and 8.5 |
| Deprecation noise in logs | `curl_close()` removed; audit table above shows no other hits |

## Rollback

Revert the single runtime commit (`FROM php:8.5-fpm-alpine` →
`php:8.4-fpm-alpine`, `"php": "^8.5"` → `"^8.2"`, re-add `curl_close()`).
No database, configuration or API changes are involved.

## Follow-ups (not part of this change)

1. Generate and commit a `composer.lock` so image builds are reproducible
   (the `Dockerfile` already has the `COPY composer.lock` line commented out).
2. Consider a CI job that runs `php -l` + `composer validate` on PHP 8.5 for
   pull requests, instead of relying on the release-time Docker build.
3. Revisit `--ignore-platform-reqs` once the vendor stage runs on the same
   PHP version as the runtime image.
